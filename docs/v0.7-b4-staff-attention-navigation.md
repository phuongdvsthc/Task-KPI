# v0.7-B4 – Staff Attention Panel & Safe Detail Navigation

## Overview
v0.7-B4 makes the Staff Dashboard actionable by introducing a factual attention panel, making appropriate summary cards interactively navigable to existing authorized detail pages, preserving context safely, and maintaining a strictly read-only dashboard posture with zero data-mutation side effects.

## 1. Attention Types Supported & Vietnamese Labels
The dashboard extracts and maps factual attention items from the Unified Dashboard API response:
- **overdue_tasks** → "Công việc quá hạn" (Count of overdue tasks, severity: warning)
- **missing_daily_reports** → "Ngày chưa có báo cáo" (Count of missing daily report days, severity: warning)
- **unread_notifications** → "Thông báo chưa đọc" (Count of unread notifications, severity: info)
- **pending_required_acknowledgements** → "Thông báo cần xác nhận" (Count of required announcement acknowledgements, severity: warning)
- **announcements_not_viewed** → "Thông báo chưa xem" (Count of unviewed announcements, severity: info)
- **kpi_pending_review** → "KPI đang chờ đánh giá" (Count of KPIs pending review, severity: info)
- **metric_data_unavailable** → "Dữ liệu chỉ số chưa sẵn sàng" (Metric data unavailable status, severity: info)

## 2. Actual Destination Routes & Navigation Mapping
- Overdue tasks → `#/tasks`
- Missing daily reports → `#/daily-reports`
- Unread notifications / acknowledgements / announcements → `#/tasks`
- KPI pending review → `#/kpis`
- Metric unavailable → `#/metrics`

**Security Constraints on Navigation:**
- No employee IDs are encoded in URLs.
- No organization unit IDs are encoded in URLs.
- No roles or reporting scopes are encoded in URLs.
- No authentication tokens or secrets are encoded in URLs.
- Date filters (`date_from`, `date_to`) are preserved only when the destination route supports them natively.

## 3. Card Interaction Policy
- **Interactive Cards**: Task summary cards, Daily-report summary cards, KPI summary cards, and Attention summary cards link safely to their respective authorized pages (`#/tasks`, `#/daily-reports`, `#/kpis`).
- **Non-Interactive Cards**: Metric snapshot cards and aggregated rate summaries without direct standalone list pages remain clean, non-interactive visual containers.
- **Accessibility**: Interactive cards have explicit `role="button"`, `tabIndex={0}`, clear `aria-label` descriptions, keyboard activation (`Enter` / `Space`), and visible focus outlines.

## 4. Read-Only Guarantee
Rendering the dashboard and navigating from cards or attention items triggers **zero** write operations:
- Does not mark notifications as read.
- Does not mark announcements as viewed.
- Does not acknowledge announcements.
- Does not change task statuses.
- Does not submit daily reports.
- Does not create metric entries or KPI reviews.

## 5. Counter Consistency & States
- Counts map directly from the backend API response (`summary.operations.attention`, `summary.operations.tasks`, etc.).
- Header notification bell count remains independent and is unaffected by dashboard renders.
- Empty attention state displays neutral message: *“Hiện không có nội dung nào cần chú ý.”*
- Partial responses preserve available attention items without defaulting missing values to zero incorrectly.

## 6. Accessibility & Responsiveness
- Designed with mobile-first Tailwind grid layouts (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`).
- No horizontal overflow. Long labels wrap safely.
- Screen readers distinguish interactive cards from static cards. Severity is indicated with text and icons alongside color.
