# v0.7-C4.1 – Manager Team Monitoring Read Service & API

## Overview
The Manager Team Monitoring Read Service & API (`GET /api/dashboard/team-monitoring`) provides a secure, read-only endpoint returning one factual monitoring row per authorized employee for Managers, Executives, and Admins.

## Contract Specification

### Endpoint
`GET /api/dashboard/team-monitoring`

### Authentication & Authorization
- Requires valid bearer token (`authenticateUser` middleware).
- Resolves reporting scope via `reportingScopeService.resolveReportingScope`.
- Restricts access to roles: `manager`, `executive`, `admin`. Staff and viewer roles receive HTTP 403 Forbidden.

### Query Parameters
- `date_from`: Start date (`YYYY-MM-DD`, default normalized to current month start).
- `date_to`: End date (`YYYY-MM-DD`, default normalized to current month end).
- `organization_unit_id`: Optional sub-unit filter within manager scope.
- `employee_id`: Optional employee filter within manager scope.
- `page`: Page number (default: `1`).
- `page_size`: Number of rows per page (default: `20`, max: `100`).
- `sort_by`: Sort field (`organization_unit_name`, `display_name`, `task_completion_rate`, `kpi_achievement_rate`, `total_tasks`).
- `sort_order`: Sort direction (`asc` or `desc`, default: `asc`).

## Safety & Performance Guarantees
1. **Read-only**: Does not perform any database writes or state mutations.
2. **Batch Processing**: Avoids N+1 queries by batch-loading profiles, memberships, tasks, daily reports, metric entries, and KPI assignments in single queries per collection.
3. **Scope Enforced**: Automatically scopes data to the authenticated manager's reporting hierarchy.
