# v0.9-B2.2-B: Team Report Mutation Routes Authorization Matrix

This document defines the capability-based authorization matrix for all write/mutation API endpoints under the Team Report (Báo cáo đội ngũ) and Daily Report modules, migrating them to Authorization Service B1.

## Summary Matrix

| No. | Method & Route | Module | Required Capability | Supported Scopes | Enforcement & Validation Rules |
|-----|----------------|--------|---------------------|------------------|--------------------------------|
| 1 | `POST /api/manager/send-reminder` | team_report | `team_report.remind` | unit_tree, all | Authenticated user; requires `team_report.remind`. Resolves data scope. Verifies `organization_unit_id` and target employee are within caller's permitted data scope (`unitIds` for `unit_tree`, or `all`). Enforces actor identity (`reminded_by = session.userId`). Enforces 60-min cooldown. |
| 2 | `POST /api/manager/send-bulk-reminders` | team_report | `team_report.remind` | unit_tree, all | Authenticated user; requires `team_report.remind`. Resolves data scope. Validates that every target in `targets` is within caller's permitted unit scope. If any target is out of scope, request is rejected with 403 Forbidden. Enforces actor identity (`reminded_by = session.userId`). |
| 3 | `POST /api/dashboard/team-monitoring/missing-report-reminder` | team_report | `team_report.remind` | unit_tree, all | Authenticated user; requires `team_report.remind`. Replaces legacy `profiles.system_role` check. Resolves data scope and verifies employee's unit memberships are within caller's scope. Enforces idempotency and server-side missing check. Enforces actor identity (`created_by = session.userId`). |
| 4 | `POST /api/manager/missing-report-reminder` | team_report | `team_report.remind` | unit_tree, all | Authenticated user; requires `team_report.remind`. Alias to missing report reminder handler. Applies identical capability and scope enforcement. |
| 5 | `POST /api/daily-reports` | team_report | authenticated / `team_report.review` | own, unit_tree, all | Authenticated user. Executive role is strictly read-only (403). Submitting own report (`user_id === session.userId`) is allowed for employees. Creating/updating another user's report ("Manager review / Ghi chú / Cập nhật báo cáo đã nộp") requires `team_report.review` and validates target employee is within caller's data scope. |
| 6 | `DELETE /api/daily-reports/:id` | team_report | authenticated / `team_report.review` | own, unit_tree, all | Authenticated user. Executive role is strictly read-only (403). Deleting own report allowed; deleting another user's report requires `team_report.review` within scope. Replaces legacy `profiles.system_role` checks. |
| 7 | `DELETE /api/daily-reports/:id/sources/:sourceId` | team_report | authenticated / `team_report.review` | own, unit_tree, all | Authenticated user. Executive role is strictly read-only (403). Deleting source in own report allowed; deleting in another user's report requires `team_report.review` within scope. Replaces legacy `profiles.system_role` checks. |

## Security Guarantees
1. **No System Role Reliance**: All permissions and scopes are evaluated using B1 Authorization Service (`getRequestAuthorizationContext`, `requirePermission`, `resolveDataScope`), eliminating direct reliance on `profiles.system_role`.
2. **Executive Restriction**: Executive role lacks mutation capabilities (`team_report.remind`, `team_report.review`), ensuring Executive remains strictly read-only across Team Report and Daily Report mutations (403 Forbidden).
3. **No Admin Bypass**: Admin permissions are verified through explicit capability grants (`team_report.remind`, `team_report.review`). Revoking an Admin's grant immediately blocks mutations with 403 Forbidden.
4. **Data Scope Enforcement**: Managers are strictly bounded by `unit_tree` scope. Sending reminders or editing reports for personnel in other branches returns 403 Forbidden.
5. **Actor Identity Integrity**: Reminded by, created by, and report ownership strictly reference the authenticated session (`res.locals.user.id`). Client-supplied spoofed IDs are rejected or overwritten.
