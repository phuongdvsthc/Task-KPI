# Documentation: v0.7-B3.2 – Staff Metric and KPI Charts

## 1. Metric Series Contract and Fields
The Metric trend chart consumes personal metric time-series data returned by the Dashboard API:
- `date`: Chronological date string (`YYYY-MM-DD`).
- `metric_id`: Unique identifier of the metric definition.
- `metric_name`: Human-readable Vietnamese name of the metric.
- `unit`: Unit of measure (e.g. `giờ`, `tiết`, `%`, `bài`).
- `value`: Numeric value recorded for that date. Preserves `null` distinctly from `0`.

## 2. Metric Selector Behavior and Reset Rules
- **Access Scope**: Shows only metrics available to the authenticated Staff member.
- **Selection Key**: Uses `metric_id` internally as the unique value.
- **Display Label**: Formats with the metric name and unit (e.g., `Giờ giảng dạy (giờ)`).
- **Multiple Metrics**: When `> 1` metric exists, provides an accessible `<select id="metric-selector">` with associated label.
- **Single Metric**: When exactly 1 metric exists, displays the metric name directly in a badge without an unnecessary selector dropdown.
- **Zero Metrics**: Displays a neutral empty state (`Chưa có dữ liệu chỉ số công việc trong kỳ báo cáo.`).
- **State Preservation**: Preserves the selected metric across refreshes. If the selected metric becomes unavailable, resets safely to the deterministic first available metric preserving API order.

## 3. Metric Trend Visualization Choice and Rationale
- **Visualization**: Line chart (`LineChart`).
- **Rationale**: Metric values represent sequential progress over time across the reporting period. A continuous line chart clearly highlights fluctuations, trends, and stability over time.
- **Rules**:
  - Shows only one selected metric at a time to prevent mixing incompatible scales or units.
  - Chronological point ordering by date.
  - Formatted date labels (`DD/MM/YYYY`).
  - Decimal precision preserved using Vietnamese locale formatting.
  - Non-clickable points (strict B3.2 scope).

## 4. KPI Period Series Contract and Fields
The KPI period series consumes discrete evaluation period summaries calculated by the backend:
- `period_id`: Identifier of the evaluation period.
- `period_name`: Name of the period (e.g., `Học kỳ I`, `Năm học 2025-2026`).
- `start_date`: Period start date (`YYYY-MM-DD`).
- `end_date`: Period end date (`YYYY-MM-DD`).
- `average_score` / `score`: Backend-calculated weighted KPI score.
- `assignment_count`: Number of KPI assignments in the period.
- `achieved_count`: Number of achieved KPI assignments.
- `source`: Result source indicator (`'official'` for locked reviews/snapshots, `'live'` for active calculations).

## 5. KPI Period Visualization Choice and Rationale
- **Visualization**: Bar chart (`BarChart`).
- **Rationale**: KPI periods are discrete evaluation cycles rather than continuous daily time steps. A bar chart provides intuitive side-by-side comparison between distinct evaluation periods without falsely implying continuity across unrelated semesters or annual cycles.
- **Rules**:
  - Ordered chronologically by period start date.
  - No 100% cap (allows overachievement if permitted by KPI Engine).
  - No fabricated 100% target line.
  - Non-clickable bars (strict B3.2 scope).

## 6. Primary KPI Measure Used
- **Authoritative Measure**: `average_score` (the weighted KPI score calculated directly by the backend).
- The frontend does not calculate or recalculate KPI scores, achievement formulas, or weights.

## 7. Live vs Official Result Representation
- **Official Result**: Labeled as **Chính thức** with an emerald badge for periods where all assignments are locked/approved reviews or official snapshots.
- **Live Result**: Labeled as **Tạm tính** with an amber badge for active evaluation periods.
- **Design**: Uses explicit text labels alongside distinctive border and background badges, ensuring status is never communicated by color alone.

## 8. Unit Handling
- Metric charts display the metric's authentic unit on the Y-axis and in tooltips.
- Metrics with different units are never combined onto a single axis.
- Dual-axis charts are strictly prohibited.

## 9. Missing Data Handling
- `null` values are kept strictly distinct from `0`.
- Missing dates or periods are never fabricated.
- Missing values are rendered as "Chưa có dữ liệu" rather than zero.
- Empty states are rendered independently per section.

## 10. Presentation Adapters
- Located in `/src/components/dashboard/staffChartAdapters.ts`.
- Pure, non-mutating adapter functions:
  - `extractAvailableMetrics(dashboardData)`
  - `adaptMetricTrendData(series, selectedMetricId, metricMeta)`
  - `adaptKpiPeriodData(kpiSeries)`
- Preserves all raw values and sorts arrays safely without mutating the source objects.

## 11. Responsive Behavior
- Responsive grid: charts display side-by-side on desktop (`lg:grid-cols-2`) and stack vertically on mobile screens.
- Flexible chart containers (`ResponsiveContainer` with 100% width and fixed 256px height).
- No horizontal page overflow.

## 12. Accessibility Features
- Visible heading and concise description for each chart section.
- Accessible data lists / summary tables beneath each chart allowing keyboard users and screen readers to access all points without requiring tooltip hover.
- Distinct textual badges for "Chính thức" and "Tạm tính".
- Associated labels on selector controls (`aria-label`, `<label>`).

## 13. Invariants Preserved
- No database schema alterations or migrations.
- No changes to RLS policies.
- No changes to backend metric or KPI calculation algorithms.
- Staff personal scope strictly enforced; no data leakage across employees.

## 14. Strict Scope Boundaries Respected
- No Manager, Admin, or BGH dashboard features added.
- No drill-down navigation or detail tables.
- No AI summaries or automated narrative text.
- No report export functionality.
- No clickable bars or points.
